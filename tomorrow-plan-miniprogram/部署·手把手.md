# 部署·手把手（跟着点）

> 这份是按「你在微信开发者工具里，鼠标该点哪」写的。
> 通用说明在 `部署指南.md`，这份是操作手册。

## 准备：你需要同时开着三个窗口

| 窗口 | 怎么打开 | 用来干嘛 |
| --- | --- | --- |
| **微信开发者工具** | 已打开 | 上传云函数 |
| **云开发控制台** | 工具顶部工具栏 → 点「**云开发**」按钮（一朵云的图标，在「编译」「预览」那一排） | 配环境变量、建集合、看日志 |
| **浏览器** | 任意 | 登录 mp.weixin.qq.com / github.com / deepseek |

> 云开发控制台是新开的一个窗口，里面左侧菜单：概览 / 数据库 / 存储 / **云函数** / 静态网站托管 / 设置。

## 第 2 步：上传三个云函数

### 在哪

开发者工具**左侧**是文件树（能看到 `pages`、`utils`、`cloudfunctions`）。
`cloudfunctions` 文件夹图标上有一个**小云朵**，说明它被识别成云函数目录。

### 怎么做

1. 展开 `cloudfunctions`，你会看到三个文件夹：`askAI`、`dailyReminder`、`pushDiary`
2. **右键点 `pushDiary`** → 弹出菜单 → 选 **「上传并部署：云端安装依赖（不上传 node_modules）」**
3. 右下角会弹进度条，等它变成「上传成功」（**30–60 秒，别中途关窗口**）
4. 对 `askAI`、`dailyReminder` 重复

### 成功后长什么样

云开发控制台 → 左侧「云函数」→ 列表里应该出现这三个函数名，每个后面有「版本号 / 更新时间」。

### 常见错误

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 菜单里没有「上传并部署」 | 这个文件夹没被识别成云函数 | 看 `project.config.json` 里 `cloudfunctionRoot` 是不是 `cloudfunctions/` |
| 报 `Cannot find module 'wx-server-sdk'` | 选成了「不上传 node_modules」那个 | 重新右键，选带「**云端安装依赖**」的那一项 |
| 报错 `env not found` | 工具顶部没选环境 | 工具栏「云开发」按钮旁边有环境下拉，选 `cloud1-d2g2zn0bm8988b897` |

## 第 3 步之一：三把钥匙怎么拿

### 🗝 钥匙 1 · DEEPSEEK_KEY（给「拆解」用）

1. 浏览器开 <https://platform.deepseek.com>
2. 微信/手机号登录 → 左侧菜单点 **「API keys」**
3. 点 **「创建 API key」** → 名字随便填（比如 `tomorrow`）→ 确定
4. 弹窗里那串 `sk-xxxxxxxx` → **点复制**
   ⚠️ 关掉弹窗就再也看不到了，**先粘到记事本里**
5. 左侧点 **「充值」**，确认余额 > 0（没余额调用会返回 402）

### 🗝 钥匙 2 · GITHUB_TOKEN（给「日记同步」用）

1. 浏览器开 <https://github.com> → 右上角**头像** → **Settings**
2. 左侧拉到最下面 → **Developer settings**
3. 左侧 **Personal access tokens** → **Fine-grained tokens**
4. 点 **Generate new token**
5. 逐项填：

   | 表单项 | 填什么 |
   | --- | --- |
   | Token name | `tomorrow-wapps` |
   | Expiration | 90 days（或更长） |
   | Repository access | **Only select repositories** → 下拉选 `tomorrow-wapps` |
   | Permissions → Repository permissions | 展开 → 找到 **Contents** → 选 **Read and write** |

6. 页面最下面点 **Generate token**
7. 出现一串 `github_pat_xxxxxxxx` → **复制**（只显示一次）

> 别用上面的「Tokens (classic)」，那个权限过大。fine-grained 只给这一个仓库的写权限。

### 🗝 钥匙 3 · SUBSCRIBE_TEMPLATE_ID（给「每晚提醒」用，可最后做）

**前置条件**：小程序必须先设好「服务类目」，否则模板库是空的。

1. 浏览器开 <https://mp.weixin.qq.com> → 扫码登录
2. 左侧 **设置** → **基本设置** → 找到「**服务类目**」→ 选一个（个人主体选「工具 > 效率」这类）→ 提交
3. 左侧 **功能** → **订阅消息**
4. 中间「**公共模板库**」搜索框输入「**待办**」
5. 找一条合适的（比如「待办事项提醒」）→ 点 **选用**
6. 选完之后，页面上会出现：
   - **模板 ID**：一串字母数字 → 复制
   - **模板内容**：里面写着字段名，比如 `thing1`、`time2` → **记下来，第 3 步之二要用**

## 第 3 步之二：把钥匙填进云函数

**位置：云开发控制台 → 左侧「云函数」→ 点击函数名 → 顶部「配置」标签页**

### pushDiary

1. 左侧云函数 → 点 **`pushDiary`**
2. 点顶部 **「配置」** 标签
3. 找到 **「环境变量」** 区域 → 点 **「添加」**，逐个加这 4 条：

   | 变量名 | 值 |
   | --- | --- |
   | `GITHUB_TOKEN` | 钥匙 2 那串 `github_pat_...` |
   | `GITHUB_REPO` | `xiaozhengmaker/tomorrow-wapps` |
   | `GITHUB_BRANCH` | `main` |
   | `GITHUB_DIR` | `Daily` |

4. 同一个「配置」页面，找到 **「超时时间」**（有的版本叫「执行超时时间」）→ 改成 **10 秒** → 保存

### askAI

同样位置：
- 环境变量加 1 条 `DEEPSEEK_KEY` = 钥匙 1
- **超时时间改成 60 秒**（这条最重要，不改基本必超时）

### dailyReminder

- 环境变量：
  - `SUBSCRIBE_TEMPLATE_ID` = 钥匙 3 的模板 ID
  - `SUBSCRIBE_DATA` = `{"thing1":{"value":"今天还没复盘"},"time2":{"value":"20:00"}}`
    （**把 `thing1`/`time2` 换成你模板里的字段名**）
  - `SUBSCRIBE_PAGE` = `pages/review/review`
- 超时时间 **20 秒**


### ⚠️ SUBSCRIBE_DATA 到底怎么填（最容易错的一步）

你申请的模板如果是这样：

| 详细内容 | 占位符 |
| --- | --- |
| 事项时间 | `{{time2.DATA}}` |
| 事项主题 | `{{thing1.DATA}}` |

那么变量名就是 **`time2`** 和 **`thing1`**（`.DATA` 是模板里的写法，**不属于变量名**）。

环境变量 `SUBSCRIBE_DATA` 的值，整行粘这个：

```json
{"thing1":{"value":"今天还没复盘"},"time2":{"value":"20:00"}}
```

规则：**每个字段都是一个 `{"value":"内容"}` 对象**。

| 常见错法 | 为什么错 |
| --- | --- |
| `{"time2.DATA":...}` | 键不能带 `.DATA` |
| `{"time2":{"20:00"}}` | 对象必须有键，写成 `{"value":"20:00"}` |
| `{"time2":"20:00"}` | 值必须是对象，不是字符串 |
| JSON 里有换行 | 环境变量里必须是一行 |

字段类型的限制（超了会报 `47003`）：

- `thing` 类：**最多 20 个字**
- `time` 类：`HH:mm` 或 `yyyy-MM-dd HH:mm`

### ⚠️ 订阅消息为什么在开发者工具里测不出来

**这是微信的限制，不是配置错了。**

1. `wx.requestSubscribeMessage` **只在真机上工作**。模拟器里点「开启今晚的提醒」一定失败。
   → 必须点工具栏「**预览**」，手机扫码，在**手机上**点授权。
2. 定时触发器 `0 0 20 * * * *` 是**云端**的，本地编译跑一万遍也不会响。
   → 想立刻验证，去云开发控制台 → 云函数 → `dailyReminder` → 「**云端测试**」手动跑。

小程序的「设置」页现在会在开发者工具里直接提示这两点，不用靠猜。

> 修改环境变量后**不用重新上传代码**，保存就生效。

## 第 4 步：建两个数据库集合

**位置：云开发控制台 → 左侧「数据库」**

### 具体操作

1. 点左侧 **「数据库」**
2. 上方有一排集合名（初始可能只有一个，或者空的），右边有一个 **「+」** 按钮 → 点它
3. 弹出「新建集合」→ 输入名字 **`diary_outbox`** → 确定
4. 再点一次「+」→ 输入 **`remind_subscribers`** → 确定
5. **设权限**：点刚建的集合名 → 顶部会出现 **「权限设置」** 标签 → 点开
   → 选 **「仅创建者可读写」** → 保存
6. 两个集合都要设一遍

### 建完长什么样

左侧「数据库」下面出现两个集合名，点进去能看到一个空表格（0 条记录）。

### 这两个集合是干嘛的

| 集合 | 作用 | 不建会怎样 |
| --- | --- | --- |
| `diary_outbox` | 每天推送的日记记一笔，推失败的留着重试 | 推送失败就丢了，没有重试 |
| `remind_subscribers` | 谁订阅了每晚提醒、还剩几条 | 「每晚微信提醒」按钮会报错 |

> 不建集合**不会让小程序崩**，只是这两个功能降级。可以先跳过，回头再补。

## 第 5 步：验证到底通没通

**位置：微信开发者工具（编译）+ 云开发控制台（看日志）**

### 5.1 验证「拆解接上 AI」

1. 开发者工具 → 底部「**拆解**」tab
2. 输入一句模板覆盖不到的话，比如「跟房东谈续租」
3. 点「**拆一下**」
4. 卡片立刻出现，右上角徽章显示「AI 拆解中…」
5. **2–5 秒后**，徽章变成「**AI 拆的**」→ ✅ 成功

**没变怎么办**：云开发控制台 → 云函数 → `askAI` → 顶部「**日志**」标签 → 看最近一条：

| 日志里的报错 | 原因 |
| --- | --- |
| `缺少环境变量 DEEPSEEK_KEY` | 第 3 步环境变量没保存 |
| `DeepSeek 返回 401` | key 复制错了 / 多了空格 |
| `DeepSeek 返回 402` | 账号没余额 |
| `请求超时` | 超时时间没改成 60 秒 |

### 5.2 验证「日记推到 GitHub」

1. 底部「**复盘**」tab → 写两句 → 点「**生成评估**」
2. 云开发控制台 → 云函数 → `pushDiary` → 「**日志**」→ 应该有一条调用记录
3. 浏览器打开 <https://github.com/xiaozhengmaker/tomorrow-wapps/tree/main/tomorrow-plan-miniprogram/Daily>
   → 应该出现一个 `2026-11-03.md` 文件
4. 点开它 —— 内容就是今天的清单 + 评估 → ✅ 成功

**没出现怎么办**：看 `pushDiary` 的日志：

| 报错 | 原因 |
| --- | --- |
| `提交失败（401）` | token 权限没给 Contents: Read and write |
| `提交失败（404）` | `GITHUB_REPO` 写错（必须是 `用户名/仓库名`） |
| `缺少环境变量` | 环境变量没保存 |

### 5.3 验证「Obsidian 收得到」

1. 电脑上找个别的地方 `git clone https://github.com/xiaozhengmaker/tomorrow-wapps.git`
2. Obsidian → 「打开文件夹作为仓库」→ 选 clone 下来的目录
3. Obsidian → 设置 → **第三方插件** → 关闭「安全模式」→ **浏览** → 搜 `Git` → 安装 → 启用
4. 插件设置里 **Auto pull interval** 填 `10`
5. 等 10 分钟（或手动点左侧 Git 图标 → Pull）→ 左侧文件树里出现 `Daily/2026-11-03.md` → ✅ 成功

### 5.4 验证「每晚微信提醒」

1. 复盘页右上角「**设置**」→ 找到「**每晚微信消息**」→ 点「开启今晚的提醒」
2. 微信弹授权框 → 点「**允许**」
3. 云开发控制台 → 数据库 → `remind_subscribers` → 应该多了一行，`left: 1`
4. 晚上 20:00 收到微信消息 → ✅ 成功

**没收到**：看 `dailyReminder` 日志 → `43101` 说明用户拒收（重新授权）；`47003` 说明 `SUBSCRIBE_DATA` 字段名跟模板不一致。

## 一句话顺序

```
上传 3 个函数  →  填 3 组环境变量 + 改超时  →  建 2 个集合  →  跑 5.1 → 5.2 → 5.3 → 5.4
```

每验完一个就打勾，出问题只看对应的那一节。
