# 部署指南

五条路，各管一件事。大多数人只需要 **A + C**；想要日记自动进 Obsidian 就加 **D**；想让拆解交给大模型就加 **E**。

| 你想要的 | 走哪条 | 大概花多久 | 花钱吗 |
| --- | --- | --- | --- |
| 只在自己手机上用 | **A 体验版** | 30 分钟（含注册） | 0 |
| 别人也能搜到、能用 | **B 正式发布** | A 之后 + 审核 1–7 天 | 0 |
| 手机日历到点响 | **C 网页版** | 5 分钟 | 0 |
| 每天自动写进 Obsidian | **D 云开发 + GitHub** | 30 分钟 | 云开发按量（个人可忽略） |
| 拆解交给大模型 | **E 接 DeepSeek** | 15 分钟 | 按 token，一次不到一分钱 |

> A/B 是微信里那个小程序，C 是 `preview.html` 那个网页，D/E 是云端函数。
> 互不依赖：只做 A 也能用；做了 E 但没做 D，日记就是手动同步。

---

## A. 只在自己手机上用（体验版）

体验版不用审核、不用认证、不用花钱，传上去扫码就能用，**之后不需要开电脑**。

### A1 注册小程序，拿到 AppID

1. 电脑打开 <https://mp.weixin.qq.com> → 右上角「立即注册」→ 选「小程序」
2. 邮箱：用一个**没注册过公众号/小程序**的邮箱（QQ 邮箱可以，但别用已经绑过的那个）
3. 主体类型选「**个人**」，填身份证和手机号，用本人微信扫码验证
4. 注册完登录后台 → 左侧「开发」→「开发管理」→「开发设置」→ 抄下 **AppID(小程序ID)**

> 名字先随便起一个，验证阶段和以后都能改。个人主体重名会提示，换个即可。

### A2 装开发者工具，导入项目

1. 下载**稳定版**：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
2. 安装打开 → 微信扫码登录
3. 「导入项目」→ 目录选 **`tomorrow-plan-miniprogram`** 这个文件夹（选到它有 `app.json` 的那一层）
4. AppID 填 A1 抄的那个 —— **不要选「测试号」**，测试号不能上传
5. 点确定 → 编译 → 模拟器里应该直接看到首页

### A3 确认工程里的 AppID

打开 `project.config.json`，看这一行：

```json
"appid": "touristappid",
```

如果导入时填了真 AppID，工具会自动改掉它。没改的话就手动换成你的 AppID。留着 `touristappid` 会导致上传失败。

### A4 上传代码

1. 工具右上角点「**上传**」
2. 版本号填 `1.0.0`，项目备注填「首个版本」
3. 等弹出「上传成功」

### A5 设成体验版，扫给自己

1. 回 <https://mp.weixin.qq.com> → 左侧「**管理**」→「**版本管理**」
2. 「开发版本」那一栏 → 点「**选为体验版**」→ 生成一个体验版二维码
3. 左侧「**管理**」→「**成员管理**」→「**体验成员**」→ 添加你自己的微信号
4. 手机微信扫那个二维码 → 就能用了

之后不用电脑也能打开：微信 →「发现」→「小程序」→ 最近使用，或者直接搜你的小程序名。

### A6 改了代码怎么更新

改完 → 工具「上传」→ 版本号加一（`1.0.1`）→ 后台「版本管理」把新版本「选为体验版」→
手机上**把小程序从后台划掉再进**（不是切到别的 App，是真的杀掉）。

## B. 正式发布（别人也能用）

在 A 已完成的基础上继续。

1. 「**设置**」→「基本设置」→「**服务类目**」：个人主体选「工具 > 效率」这一类，按提示填一句用途说明
2. 「**版本管理**」→「**提交审核**」
   - 功能页面：把每个页面都点一遍，确认没有半成品按钮（审核员真的会点）
   - 测试账号：没有登录体系就写「无需登录」
   - 补充说明建议原话：「本地待办清单工具，数据只保存在用户手机本地，不联网、不收集用户信息」
3. 审核一般 1–7 天，通过后回到「版本管理」点「**发布**」
4. 发布后别人在微信里搜名字就能用

注意：

- **类目不对会被驳回**，个人主体可选「工具」下几类，选中一个贴近的
- 小程序**没有网络请求**（这一点在审核时是加分项，不是扣分项）
- 认证不是发布的前提，但客服、支付这类能力需要，用不到就不用办
- 价格、菜单名以官方页面当前显示的为准，微信后台改版比较勤

## C. 网页版（手机日历提醒只能从这里出）

小程序**生成不了文件**，所以「明天的清单 .ics」和「每日复盘提醒 .ics」都在 `preview.html` 里。

### C1 必须整个文件夹一起传

`preview.html` 直接加载同级的 `utils/` 里的代码：

```
preview.html   需要  utils/parser.js
                     utils/date.js
                     utils/ics.js
                     utils/breakdown.js
                     utils/review.js
                     utils/progress.js
```

**只传一个 html 文件会白屏。** 把整个 `tomorrow-plan-miniprogram` 文件夹传上去最省事
（`tests/` 传上去也无所谓，没有密钥）。

### C2 最省事：Netlify Drop（30 秒）

1. 电脑打开 <https://app.netlify.com/drop>
2. 把整个 `tomorrow-plan-miniprogram` 文件夹**拖进页面**
3. 等十几秒，得到一个 `https://xxxx.netlify.app` 网址

不用注册也能生成，想长期保留再注册。

### C3 国内访问更稳：腾讯云 COS

1. 腾讯云控制台 →「对象存储」→ 新建存储桶
   - 地域选离你近的
   - 访问权限选「**公有读私有写**」
2. 进入存储桶 →「文件列表」→ 上传整个文件夹（保持 `utils/` 目录结构）
3. 「基础配置」→「静态网站」→ 开启 → 索引文档填 `preview.html`
4. 用页面给出的**访问域名**打开

想用自定义域名的话需要备案，用默认域名就不需要。

### C4 在手机上用起来

1. 手机浏览器打开那个网址（Safari / Chrome，**不要用微信内置浏览器**）
2. 写下明天要做的事 → 点「生成明日清单」
3. 要每日复盘提醒：时间框选 `20:00` → 点「每日复盘提醒」→ 下载 `.ics`
4. 系统弹「加入日历」→ 确认

之后每天 20:00 响的是**系统日历**，跟电脑、跟小程序开不开都没关系。

## D. 云开发 + GitHub（每天自动进 Obsidian）

做完这节你会得到：**在小程序里生成复盘 → 自动推到 GitHub → Obsidian 里 pull 一下就有**。
不用买服务器、不用域名、不用备案。

### D1 开通云开发

1. 微信开发者工具左上角点「**云开发**」
2. 开通 → 新建环境（名字随便，地域选离你近的）
3. 复制**环境 ID**（形如 `cloud1-9gxxxxxxxxxx`）
4. 打开 `utils/cloud.js`，把最上面这行填上：

   ```js
   var ENV = 'cloud1-9gxxxxxxxxxx'
   ```

> 计费方式开通时看清：个人这个用量（每天几次调用 + 一次定时任务）基本可以忽略，
> 但免费额度和套餐政策会变，以控制台当前显示为准。

### D2 建一个 GitHub 仓库

1. GitHub → New repository → 名字比如 `obsidian-notes` → 选 **Private** → Create
2. 记下 `你的用户名/obsidian-notes`

### D3 生成一个「只能写这一个仓库」的 token

1. GitHub → 右上角头像 → **Settings** → **Developer settings**
   → **Personal access tokens** → **Fine-grained tokens** → Generate new token
2. **Repository access** 选 `Only select repositories` → 选 `obsidian-notes`
3. **Permissions** → Repository permissions → 找到 **Contents** → 选 **Read and write**
4. 有效期按需（90 天 / 一年）
5. 生成后**立刻复制**——关掉页面就再也看不到了

> 别用 classic token，那个权限太大。fine-grained 只给这一个仓库的内容写权限，
> 万一泄露，别人也只能改这一个仓库。

### D4 部署云函数

1. 开发者工具左侧文件树 → 右键 `cloudfunctions/pushDiary`
   → **「上传并部署：云端安装依赖」**
   （因为这个函数依赖 `wx-server-sdk`，不能选「不上传依赖」）
2. 云开发控制台 → 云函数 → `pushDiary` → **配置**：
   - **环境变量**，加四个：

     | 变量 | 值 |
     | --- | --- |
     | `GITHUB_TOKEN` | D3 复制的 token |
     | `GITHUB_REPO` | `你的用户名/obsidian-notes` |
     | `GITHUB_BRANCH` | `main` |
     | `GITHUB_DIR` | `Daily` |

   - **超时时间**改成 **10 秒**。默认只有几秒，一次提交要两三个网络往返，容易卡在超时。
3. 云开发控制台 → **数据库** → 新建集合 **`diary_outbox`** → 权限选「仅创建者可读写」

> `diary_outbox` 是干什么的：每推一次就记一笔。推成功标 `pushed: true`；
> 推失败就留着，晚上 23:40 的定时器会重试。没建这个集合也不会报错，只是没有兜底重试。

### D5 定时器

`cloudfunctions/pushDiary/config.json` 里已经写好了：

```json
"config": "0 40 23 * * * *"
```

七个字段依次是 **秒 分 时 日 月 周 年**，这行意思是每天 23:40:00。
想换时间就改这行，改完重新上传一次函数。

### D6 接 Obsidian

1. 电脑上把仓库 clone 到一个目录，比如 `D:\obsidian-notes`
2. Obsidian →「打开文件夹作为仓库」→ 选这个目录（也可以放进你现有的 vault 里）
3. Obsidian → 设置 → 第三方插件 → 关闭安全模式 → 浏览 → 搜 **Git** → 安装并启用
4. 插件设置里 **Auto pull interval** 填 `10`（分钟）；不想自动就在需要时点一下 pull

### D7 跑一遍确认

1. 小程序里生成一次复盘
2. 云开发控制台 → 云函数 → `pushDiary` → 日志，应该能看到一次调用
3. GitHub 仓库里出现 `Daily/2026-10-30.md`
4. Obsidian 里 pull 一下，文件就在 vault 里了

### 关于「自动」到底有多自动

- 你在小程序里点「生成评估」的那一刻，**已经在推了**，不用再点别的按钮
- 推失败（网断了、token 过期了）：云函数把它记在 `diary_outbox` 里，当天 23:40 重试一次
- **你没打开小程序那天不会生成日记**——数据在手机本地，云端拿不到。这条绕不过去，
  除非把清单也做成实时同步到云数据库（那是另一个量级的改动）

## E. 接 DeepSeek（拆解从模板变真理解）

### E0 先说清楚会发生什么

- 你点「拆一下」：**本地模板立刻出卡片**，0 延迟，不用盯着转圈
- 同一时间后台在问 DeepSeek，回来了就把三步替换掉，徽章从模板名变成「**AI 拆的**」
- DeepSeek 挂了 / 没配 key / 超时：安静地保持模板版本，一点不影响用
- **复盘仍然是本地规则，不走 AI**——大模型很容易滑回「你真棒」「建议你下次」那种语气，
  而你要的是中性陈述。这是故意的取舍。

### E1 拿 DeepSeek API Key

1. 打开 <https://platform.deepseek.com>（DeepSeek 开放平台，和聊天网页不是一个地方）
2. 注册 / 登录 → 左侧 **API keys** → **创建 API key**
3. 名字随便填 → 创建 → **立刻复制**（关掉弹窗就再也看不到）
4. 左侧 **充值**：确认账户里有余额，没余额调用会返回 402

### E2 部署云函数

1. 开发者工具左侧文件树 → 右键 `cloudfunctions/askAI`
2. 选 **「上传并部署：云端安装依赖」**
   （这个函数依赖 `wx-server-sdk`，选「不上传依赖」会报模块找不到）
3. 等右下角提示上传成功

### E3 配环境变量

云开发控制台 → 云函数 → `askAI` → **配置** → **环境变量**：

| 变量 | 值 |
| --- | --- |
| `DEEPSEEK_KEY` | E1 复制的 key |
| `DEEPSEEK_MODEL` | 选填，不填默认 `deepseek-chat` |
| `ALLOWED_OPENID` | 选填，先留空，E7 再加 |

保存。

### E4 把超时调到 60 秒（必做）

还是「配置」页 → **超时时间** → 改成 **60 秒**。

默认只有几秒，而大模型一次要 3–10 秒。**不改这一项，功能大概率一直超时。**

### E5 先在控制台自测一发

云开发控制台 → 云函数 → `askAI` → **云端测试** → 测试参数填：

```json
{
  "system": "只输出 JSON，格式 {\"steps\":[{\"text\":\"做什么\",\"minutes\":15}]}",
  "user": "把季度复盘会开得有个结果",
  "maxTokens": 300
}
```

点「运行测试」，返回里能看到 `"ok": true` 和 `text` 就通了。

对不上就按错误码查：

| 返回 | 原因 |
| --- | --- |
| `缺少环境变量 DEEPSEEK_KEY` | E3 没保存成功 |
| `DeepSeek 返回 401` | key 复制错了 / 多了空格 |
| `DeepSeek 返回 402` | 账户没余额，去充值 |
| `DeepSeek 返回 429` | 请求太频繁，等一会儿 |
| `请求超时` | E4 没改 |
| `没有权限：openid 不在白名单里` | 你把 `ALLOWED_OPENID` 填上了，先清空 |

### E6 在小程序里试

1. 编译 → 底部「拆解」tab
2. 输入一句没被模板覆盖的话，比如「跟房东谈一下续租」
3. 点「拆一下」：卡片立刻出来，徽章显示「AI 拆解中…」
4. 两三秒后徽章变成「AI 拆的」，三步换成了模型给的内容

**没变？** 云开发控制台 → 云函数 → `askAI` → 日志，看那一次调用的报错。

### E7 加白名单（可选，但建议）

不配白名单的话，任何能打开你小程序的人都能调这个函数刷你的余额。

1. 先用小程序正常拆一次，让函数跑一遍
2. 云开发控制台 → 云函数 → `askAI` → **日志** → 找到那行 `[askAI] openid = oXXXX...`
3. 复制那个 `o` 开头的字符串
4. 配置 → 环境变量 → 加 `ALLOWED_OPENID` = 你的 openid（多个用英文逗号分隔）

之后再配就是「只有你能用」。

### E8 费用

按 token 计费，`deepseek-chat` 是这个价格档里最便宜的一档。
一次拆解大概几百个 token，**一次不到一分钱**，具体以官网价格页为准。
个人每天拆两三次，一个月的费用通常低于一杯水。

自测阶段可以在平台上设一个额度上限，防止忘了关。

## F. 每晚微信推送（订阅消息）

先说清楚这条路的性质：**微信的「一次性订阅」，用户点一次「允许」只能换一条推送。**
想每晚都收到，就得每晚在小程序里点一次授权。这是平台规则，不是实现偷懒——
长期订阅只对政务、医疗这类特定类目开放，个人主体拿不到。

所以最终体验是：**晚上你在设置页点一下「开启今晚的提醒」，20:00 微信弹一条。**
比系统日历那条（导一次管很久）麻烦，但它是在微信里弹，点开就回到复盘页。

### F1 申请订阅消息模板

1. 登录 <https://mp.weixin.qq.com> → 左侧「**功能**」→「**订阅消息**」
2. 到「公共模板库」搜「待办」「提醒」，选一个类目匹配的
   （个人主体在「工具」类目下一般能选到「待办事项提醒」这类）
3. 点「选用」→ 记下两样东西：
   - **模板 ID**（一长串字符）
   - **字段名**，比如 `thing1`、`time2` —— 后面填数据必须用这个名

> 字段有格式要求：`thing` 类型最多 20 个字，`time` 类型要时间格式。填错会报 `47003`。

### F2 填模板 ID

打开 `utils/cloud.js`，第二行：

```js
var SUBSCRIBE_TEMPLATE_ID = '你的模板ID'
```

不填的话，设置页那个按钮会提示你去配。

### F3 部署云函数

右键 `cloudfunctions/dailyReminder` → **「上传并部署：云端安装依赖」**。

### F4 配环境变量

云开发控制台 → 云函数 → `dailyReminder` → 配置 → 环境变量：

| 变量 | 值 |
| --- | --- |
| `SUBSCRIBE_TEMPLATE_ID` | F1 的模板 ID |
| `SUBSCRIBE_PAGE` | `pages/review/review`（点消息打开哪页） |
| `SUBSCRIBE_DATA` | `{"thing1":{"value":"今天还没复盘"},"time2":{"value":"20:00"}}` |

`SUBSCRIBE_DATA` 里的字段名**必须换成你模板里的**。先跑通再美化。

超时时间改成 **20 秒**就够。

### F5 建集合

云开发控制台 → 数据库 → 新建集合 **`remind_subscribers`** → 权限「仅创建者可读写」。

每行存一个人：`openid`、`left`（还剩几条额度）。发一条扣一条。

### F6 定时器

`cloudfunctions/dailyReminder/config.json` 里已经写好了：

```json
"config": "0 0 20 * * * *"
```

七个字段是 **秒 分 时 日 月 周 年**，这行 = 每天 20:00:00。
想跟设置页里的时间一致，记得两边一起改。

### F7 试一次

1. 小程序 → 复盘页右上角「设置」→「每晚微信消息」
2. 点「开启今晚的提醒」→ 微信弹授权框 → 允许
3. 云开发控制台 → 数据库 → `remind_subscribers`，应该多了一行 `left: 1`
4. 等到 20:00（或去控制台手动「云端测试」跑一次定时逻辑）

### F8 常见报错

| 报错 | 原因 |
| --- | --- |
| `43101` | 用户拒收 / 额度用完了，要重新授权 |
| `47003` | `SUBSCRIBE_DATA` 的字段名或格式和模板不一致 |
| `40003` | openid 不对 |
| `缺少环境变量 SUBSCRIBE_TEMPLATE_ID` | F4 没保存 |

> 43101 之后这个人的 `left` 会被置 0，不会再天天失败重试。

## G. 传到 GitHub（顺手把网页版托管了）

放 GitHub 是一举两得：版本管理 + **GitHub Pages 直接托管 `preview.html`**，
C 节那件"网页版要用 `.ics` 导出"的事就顺手解决了。

### G1 建仓库

GitHub → New repository → 名字比如 `tomorrow-plan` →
**不要**勾 "Add a README file"（本地已经有了）→ Create。

### G2 提交并推送

本地仓库**已经初始化好、文件也暂存好了**，只剩提交和推送：


## 数据存在哪

| | 存在哪 | 会丢吗 |
| --- | --- | --- |
| 小程序 | 手机本地（`wx.setStorageSync`） | 换手机、卸载、清微信缓存都会没 |
| 网页版 | 不落库 | 刷新就还原 |

两边**不互通**，各存各的。这是纯本地方案的性质，不是 bug。

## 常见故障

**上传按钮是灰的**
→ 没登录微信；或登录的微信号不是这个小程序的开发者/管理员；或 AppID 还是 `touristappid`。

**手机扫码提示「无权限访问」**
→ 你的微信没被加进「体验成员」。加完要重新扫码。

**改了代码，手机上没变化**
→ ① 后台有没有把新版本「选为体验版」；② 要**杀掉小程序重进**，切后台不算。

**网页版打开是白屏**
→ 只传了 html，没带 `utils/` 目录；或者目录层级不对（`utils/` 必须和 `preview.html` 同级）。

**手机上点「每日复盘提醒」没反应**
→ 微信内置浏览器不支持下载文件。复制网址，用系统浏览器（Safari / Chrome）打开。

**导入项目后编译报错「app.json 未找到」**
→ 目录选深了一层或浅了一层。要选到**直接包含 `app.json`** 的那个文件夹。

**代码包太大**
→ 这个项目打出来的包约 **110KB**，不用担心（上限 2MB）。`tests/`、`preview.html`、两份 md 已经在
`project.config.json` 的 `packOptions.ignore` 里排除了，不会被打进小程序。
